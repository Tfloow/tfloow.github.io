As Large Language Models (LLMs) keep growing, figuring out how to deploy them without burning through massive amounts of VRAM has become a huge challenge. To tackle this, I developed **Auto-ADPQ** (Adaptive Post-Training Quantization)—a Python package that implements a zero-shot, calibration-free method to compress LLMs down to 4-bit precision without ruining model quality.

This project started as part of my master's thesis, where I wanted to replicate and build upon the core ideas from the paper [*"AdpQ: A Zero-shot Calibration Free Adaptive Post Training Quantization Method for LLMs"*](https://arxiv.org/abs/2405.13358). The implementation is now fully open-source and available on [PyPI](https://pypi.org/project/auto-adpq/) and [GitHub](https://github.com/Tfloow/auto_adpq).

## The VRAM Bottleneck

If you've tried running modern open-weights models like Llama 3.1 (8B), you know the memory requirements can be prohibitive:
- **16-bit (bfloat16)**: ~16GB VRAM
- **8-bit**: ~8GB VRAM
- **4-bit**: ~4GB VRAM

The problem with standard quantization methods is the trade-off: you either need a dedicated calibration dataset to keep the model smart, or you skip the data and watch the model's output quality fall off a cliff. Auto-ADPQ gets around this by using a mathematical trick—specifically, an adaptive outlier detection mechanism inspired by LASSO optimization.

## How Auto-ADPQ Works Under the Hood

Instead of feeding a dataset through the model to see which weights matter most (traditional calibration), Auto-ADPQ analyzes the weight matrices directly to isolate and protect outlier values.

### 1. Outlier Detection via LASSO

The algorithm breaks the weight matrices into distinct groups and applies a LASSO-inspired optimization to pinpoint the outliers:

$$
\text{minimize} \quad \|\mathbf{w}\|_0 + \lambda' \|\mathbf{w}\|_1
$$

It solves this using a bisection method (similar to Brent's method) to dial in the perfect regularization parameter $$\lambda'$$ for a target outlier ratio $$\alpha$$.

### 2. A Two-Tier Quantization Scheme

Once the outliers are identified, the matrix is split:
- **Normal values**: Quantized straight down to 4 bits using standard symmetric or asymmetric quantization.
- **Outliers**: Kept at a higher precision to preserve the critical information that stops the model from hallucinating.

### 3. Storage Layout

The final quantized weights are saved in a custom format containing the compressed non-outlier weights (optionally bit-packed), the exact indices and values of the saved outliers, and the scale/zero-point parameters per group.

## Quick Start

You can grab the package directly via pip:

```bash
pip install auto_adpq
```

Here's a minimal example to quantize a model:

```python
from auto_adpq import Auto_AdpQ, AutoAdpQConfig
from transformers import AutoModelForCausalLM

# Configure quantization
config = AutoAdpQConfig(
    group_size=128,
    n_iters=250,
    alpha=0.05,  # 5% outlier ratio
    q_bit=4,
    symmetrical_quantization=True,
)

# Load and quantize model
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B",
    torch_dtype="bfloat16"
)

# Apply quantization (virtual/simulated)
Auto_AdpQ.apply_quantization(model, config, multi_threaded=16)

# Push to HuggingFace Hub
model.push_to_hub("your-username/llama-3.1-8b-adpq-4bit")
```

A few things worth knowing about the package: it doesn't need a calibration set, the outlier threshold is picked automatically, quantization can run multi-threaded across layers, both symmetric and asymmetric modes are supported, and it's sitting at 91% test coverage. Docs are on [ReadTheDocs](https://auto-adpq.readthedocs.io/en/latest/) if you want more detail than this post gives.

## A closer look at the code
 
### The bisection search
 
The core of the outlier detection lives in `lasso_outlier_detection`, which searches for the regularization parameter that hits the target outlier ratio:
 
```python
def lasso_outlier_detection(self, matrix):
    """Detect outliers using LASSO-inspired optimization."""
    x0, x1 = 0.0, np.max(np.abs(matrix))
    target_outlier = self.alpha * matrix.size
    
    # Bisection loop
    for iteration in range(self.n_iters):
        n_outlier = self._optimization_function_fast(matrix, x1)
        fx1 = n_outlier - target_outlier
        
        if abs(fx1) < tolerance:
            break
            
        # Brent-like interpolation
        x_new = self._brent_function(x1, x0, fx1, fx0)
        x0, x1 = x1, x_new
    
    return outlier_mask, lambda_prime
```
 
### Quantizing a group
 
Weights are processed in groups of 128 by default, each with its own scale:
 
```python
def quantize(self, sub_vector):
    """Quantize a group of weights."""
    if self.symmetrical_quantization:
        max_abs = np.max(np.abs(sub_vector))
        scale = (2**(self.q_bit - 1) - 1) / max_abs
        quantized = np.round(scale * sub_vector).astype(np.int8)
        return quantized, scale, np.nan
```
 
## What was actually hard about this
 
Packing 4-bit values into 8-bit integers sounds trivial until you try to write the serialization and deserialization yourself — that was issue #1 on the repo, and it took a few false starts before I got it right.
 
Speed was the other recurring problem. Outlier detection has to run on every single weight group, so I ended up parallelizing across layers (16 workers by default), pushing as much as possible into vectorized NumPy instead of Python loops, and writing a separate fast path (`_optimization_function_fast`) that counts outliers without ever building the full mask.
 
On the testing side, I've got unit tests for quantize/dequantize, integration tests against real model weights, and perplexity checks on WikiText-2 — enough to get to 91% coverage and enough that I trust the numbers above.

## Wrapping up
 
Calibration-free quantization turns out to be a real option, not just a theoretical nice-to-have — Auto-ADPQ gets close to methods that do use calibration data. It's most useful when you don't have representative calibration data on hand, want to experiment with quantization settings quickly, or just want a lightweight pipeline without extra dependencies.
